# نبض الفهم | بنك الأسئلة التفاعلي الذكي للمعلم

> **اسأل، شارك، افهم**

تطبيق ويب تقدمي (PWA) يعمل على الهاتف والآيباد والكمبيوتر من المتصفح. يطرح المعلم سؤالًا قصيرًا أثناء الحصة، فيجيب الطلاب من أجهزتهم دون حسابات، وتظهر للمعلم فورًا مؤشرات الفهم (أخضر/أصفر/أحمر) مع اقتراح الإجراء التعليمي المناسب.

## ما الذي يقدمه التطبيق

**للمعلم (بحساب):**
- لوحة رئيسية: ابدأ حصة جديدة، **اختبر فهمهم الآن**، بنك الأسئلة، المفضلة، تقاريري، استيراد الأسئلة، الإعدادات، الحصص السابقة، إحصاءات مختصرة، وبحث سريع.
- **بنك أسئلة دائم** في قاعدة البيانات: إضافة، تعديل، حذف بعد التأكيد، نسخ، مفضلة، بحث، تصفية (المادة، الصف، الدرس، النوع، الصعوبة، المستوى المعرفي، المجال)، صور، تلميح، تفسير، درجة، زمن.
- **14 نوعًا من الأسئلة**: اختيار من متعدد (2–6)، صح/خطأ، اختيار متعدد الإجابات، إجابة قصيرة، مفتوح، إكمال الفراغ، ترتيب، توصيل، سؤال على صورة، سؤال على نص/آية/حديث، تعليل، تفكير ناقد، موقف حياتي، سؤال خروج.
- **التصحيح الآلي** للأسئلة الموضوعية (مع تجاهل التشكيل والهمزات في الإجابات النصية)، و**تصحيح يدوي** للأسئلة المفتوحة. لا يُستخدم الذكاء الاصطناعي في الحكم على الإجابات.
- **دعم التربية الإسلامية**: مجالات (القرآن الكريم وعلومه، التفسير، الحديث، العقيدة، الفقه، السيرة، الأخلاق) و8 قوالب أسئلة. النصوص الشرعية يدخلها المعلم بنفسه مع مصدرها، وتُحفظ وتُعرض **حرفيًا دون أي تعديل**. التطبيق لا يولّد آيات أو أحاديث أو أحكامًا.
- **الحصة المباشرة**: رمز عشوائي فريد ورابط وQR، عدد المنضمين لحظيًا، إرسال السؤال، مؤقت اختياري (يُلغى عند الحاجة)، إغلاق، كشف الإجابة، إعادة المحاولة، التالي، سؤال مفاجئ، إنهاء الحصة.
- **مؤشرات الفهم**: المشاركون، من أجاب ومن لم يُجب، الصحيح والخاطئ، النسبة، توزيع الخيارات بالرسم، الأكثر اختيارًا، الخطأ الشائع، متوسط زمن الإجابة (يُقاس في الخادم)، وطلاب يحتاجون دعمًا — مع حدود قابلة للتعديل (افتراضيًا 80% و50%).
- **شاشة العرض** لجهاز العرض: خط كبير، QR، مؤشر مشاركة، إخفاء النتائج حتى الإغلاق، أسماء مستعارة.
- **الأسئلة المفتوحة**: قائمة، بطاقات، سحابة كلمات عربية، ومراجعة واعتماد قبل العرض العام، وتنبيه على الإجابات التي قد تحتوي رقم هاتف أو بريدًا أو رابطًا.
- **الألعاب (اختيارية)**: تحدي الخمس ثوانٍ، سؤال النجاة، السؤال الذهبي (×2)، تحدي الفرق، سلسلة الإجابات الصحيحة، سؤال المفاجأة، بطاقة الحظ، سؤال نهاية الحصة. النقاط لا تعتمد على السرعة.
- **التقارير**: ملخص محفوظ لكل حصة، صحة كل سؤال، الأسئلة الأصعب، مفاهيم لإعادة التدريس، نتائج فردية (للمعلم فقط)، توصيات، ملاحظات، تصدير **CSV** و**Excel (.xlsx)** وطباعة، ومقارنة نتائج الصف عبر الحصص.
- **الاستيراد** من CSV أو JSON مع تحقق من كل صف وقالب نموذجي.

**للطالب (بدون حساب):** يدخل بالرابط أو الرمز، يكتب اسمه (أو يحصل على اسم مستعار في الحصص المجهولة)، يرى السؤال الحالي فقط، يجيب ويتلقى تأكيدًا **بعد وصول الإجابة للخادم فقط**. عند انقطاع الإنترنت تُحفظ الإجابة على جهازه وتُرسل تلقائيًا عند عودة الاتصال دون تكرار.

### قاعدة البيانات
`profiles` · `subjects` · `classes` · `questions` · `question_options` · `sessions` · `session_teams` · `session_questions` · `participants` · `responses` · `reports` · `session_signals` · `join_attempts`

قرارات تصميم مهمة:
- **`session_questions.snapshot`**: نسخة مجمدة من السؤال لحظة إرساله؛ فتعديل السؤال أو حذفه من البنك لاحقًا لا يغيّر نتائج الحصص السابقة. وقبل الإرسال تُحدَّث النسخة من البنك، فيستطيع المعلم تعديل السؤال حتى لحظة إرساله.
- **`unique (sq_id, participant_id)`** في `responses` + معرّف طلب (`client_request_id`) لكل محاولة: يمنعان تسجيل الإجابة نفسها مرتين بسبب الضغط المتكرر أو إعادة الاتصال.
- **الطالب لا يملك حسابًا**: ينضم عبر الدالة `join_session` ويحصل على رمز سري (يُخزَّن في قاعدة البيانات مُجزَّأً SHA‑256 فقط). كل عمليات الطالب تمر عبر 4 دوال فقط تتحقق من هذا الرمز.
- اخترنا هذا بدل «الدخول المجهول» في Supabase لأن حدّه الافتراضي 30 تسجيلًا في الساعة لكل عنوان IP، وطلاب الفصل غالبًا يشتركون في عنوان IP واحد.

## إنشاء مشروع Supabase وربطه

1. أنشئ حسابًا في <https://supabase.com> ثم **New project** (اختر أقرب منطقة، واحفظ كلمة مرور قاعدة البيانات).
2. **تطبيق قاعدة البيانات** — اختر طريقة واحدة:
   - **من لوحة التحكم:** افتح **SQL Editor**، والصق محتوى كل ملف من `supabase/migrations/` **بالترتيب** (001 ثم 002 ثم 003) واضغط **Run** لكل ملف.
   - **أو من سطر الأوامر:**
     ```bash
     npx supabase login
     npx supabase link --project-ref <PROJECT-REF>
     npx supabase db push
     ```
3. **المفاتيح:** من **Project Settings → API** انسخ **Project URL** و**anon / publishable key**.
   ⚠️ لا تستخدم **service_role key** في التطبيق أبدًا؛ التطبيق لا يحتاجه.
4. **المصادقة:** في **Authentication → URL Configuration**:
   - **Site URL**: رابط موقعك (مثلًا `https://nabd.vercel.app`) أو `http://localhost:5173` أثناء التطوير.
   - أضف إلى **Redirect URLs**: `https://<موقعك>/**` و`http://localhost:5173/**`.
   - تأكيد البريد مفعّل افتراضيًا: سيصل المعلم بريد تفعيل قبل أول دخول. (يمكن تعطيله من **Authentication → Providers → Email → Confirm email** للتجربة فقط.)
   - للإنتاج: اضبط خادم بريد (SMTP) من **Authentication → Emails → SMTP Settings**؛ خادم Supabase الافتراضي محدود بعدد قليل من الرسائل في الساعة.
5. **Realtime:** الترحيل الثالث يضيف الجداول اللازمة إلى `supabase_realtime` تلقائيًا. للتحقق: **Database → Publications → supabase_realtime** يجب أن تظهر فيه: `responses`, `participants`, `session_signals`, `session_questions`, `sessions`.
6. **التخزين:** الترحيل ينشئ حاوية عامة `question-images` (حتى 3 ميجابايت للصورة) بسياسات تسمح لكل معلم بالرفع داخل مجلده فقط. تحقق منها في **Storage**.

## التشغيل المحلي

المتطلبات: Node.js 20 أو أحدث.

```bash
npm install
cp .env.example .env      # ثم ضع VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY
npm run dev               # http://localhost:5173
```

لتجربة الطلاب من هواتف حقيقية على نفس شبكة Wi‑Fi: يعرض `npm run dev` عنوانًا مثل `http://192.168.1.20:5173`. افتح لوحة المعلم بهذا العنوان (وليس localhost) حتى يحمل رمز QR العنوان الصحيح، أو اضبط `VITE_PUBLIC_APP_URL`. أضف العنوان إلى Redirect URLs في Supabase.

أوامر أخرى:
```bash
npm run build      # فحص الأنواع + بناء الإنتاج في dist/
npm run preview    # معاينة نسخة الإنتاج
npm test           # اختبارات الوحدات (Vitest)
npm run test:db    # اختبارات قاعدة البيانات (تحتاج PostgreSQL)
npm run test:e2e   # اختبارات المتصفح (تحتاج بيئة Supabase، انظر tests/e2e/README.md)
```

## النشر على Vercel

1. ارفع المشروع إلى مستودع GitHub.
2. في <https://vercel.com>: **Add New → Project** واختر المستودع (يتعرف على Vite تلقائيًا).
3. في **Environment Variables** أضف:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   - (اختياري) `VITE_PUBLIC_APP_URL` = رابط موقعك النهائي.
4. **Deploy**. ملف `vercel.json` يضبط توجيه الصفحات (SPA) وترويسات أمان.
5. ارجع إلى Supabase وضع رابط Vercel في **Site URL** و**Redirect URLs**.
6. على الهاتف: افتح الموقع ← «إضافة إلى الشاشة الرئيسية» ليعمل كتطبيق.

## اختبار الاتصال بين المعلم والطلاب

1. على الكمبيوتر: أنشئ حساب معلم وادخل.
2. **اختبر فهمهم الآن** ← اكتب سؤالًا صح/خطأ ← **ابدأ الآن**.
3. اضغط **شاشة العرض** واعرضها على جهاز العرض (يظهر الرمز وQR).
4. من 3 هواتف مختلفة (أو نوافذ تصفح خفي): امسح QR أو افتح `/join` واكتب الرمز، ثم الاسم.
5. تحقق أن عدد المنضمين يزيد لدى المعلم **دون تحديث الصفحة**.
6. أجب من كل هاتف، وتحقق من ظهور «تم استلام إجابتك» ثم تحديث «أجاب 3 من 3» والرسم البياني لدى المعلم.
7. **إغلاق السؤال** ← **إظهار الإجابة الصحيحة** ← يرى كل طالب نتيجته هو فقط.
8. جرّب الانقطاع: افصل الإنترنت عن هاتف، اختر إجابة وأرسل؛ تظهر رسالة «ستُرسل تلقائيًا»، أعد الاتصال فتصل مرة واحدة.
9. **إنهاء الحصة** ← يُفتح التقرير ← صدّر Excel/CSV ← ارجع إليه لاحقًا من **تقاريري**.

مؤشر المزامنة في رأس لوحة الحصة: **«مزامنة لحظية»** يعني أن Realtime يعمل؛ **«تحديث دوري»** يعني أن التطبيق يعمل بالاحتياطي (تحديث كل 3 ثوانٍ تقريبًا). لو ظهر «تحديث دوري» على Supabase الحقيقي فراجع الخطوة 5 في الإعداد.

## الأمان والخصوصية

- **RLS مفعّل على كل الجداول.** كل معلم يرى بياناته فقط، والتحقق في قاعدة البيانات لا في الواجهة.
- الطالب (دور `anon`) **لا يملك صلاحية قراءة أي جدول** سوى أرقام إصدار المزامنة. الأسئلة تصله عبر `student_state` التي لا ترسل الإجابات الصحيحة إلا بعد أن يكشفها المعلم، وترسل أسئلة الترتيب بترتيب مختلط، وأسئلة التوصيل دون كشف الأزواج.
- الطالب يرى نتيجته هو فقط، ولا يرى إجابات زملائه أو درجاتهم.
- المعلم لا يستطيع تعديل الدرجة مباشرة؛ التعديل عبر دالة التصحيح فقط.
- رموز الحصص من 6 أحرف بدون الأحرف الملتبسة، والحصص المنتهية ترفض الانضمام، و**20 محاولة خاطئة خلال 10 دقائق** من نفس العنوان توقف المحاولات مؤقتًا.
- رمز المشارك السري يُحفظ مُجزَّأً فقط.
- الحماية من حقن الصيغ عند فتح ملفات CSV في Excel.
- لا توجد أي مفاتيح سرية في الواجهة.

**ملاحظة:** صور الأسئلة في حاوية عامة (حتى يراها الطلاب دون حساب)، فلا ترفع صورًا تحتوي معلومات شخصية.

## حالة الاختبار وما بقي

**ما اختُبر فعليًا (في بيئة التطوير):**
- ترحيلات قاعدة البيانات طُبقت على PostgreSQL 16 ونجحت 24 اختبارًا.
- 17 اختبار وحدة، وبناء الإنتاج دون أخطاء.
- السيناريو الكامل في متصفح Chromium حقيقي مع **خادم المصادقة الرسمي من Supabase (GoTrue)** و**PostgREST** (نفس مكونات Supabase) على قاعدة البيانات المحلية: تسجيل المعلم ودخوله، إنشاء الأسئلة وتعديلها، إنشاء الحصة، انضمام 3 طلاب من 3 أجهزة، ظهور الإجابات والإحصاءات دون تحديث، الإغلاق والكشف، التالي، الأسئلة المفتوحة وسحابة الكلمات، إنهاء الحصة، التقرير، التصدير، والعرض على الهاتف والآيباد.

**ما لم يُختبر بعد (يحتاج مشروع Supabase حقيقيًا):**
- **Supabase Realtime (WebSocket)**: لم يتوفر خادمه في بيئة التطوير، فجرى الاختبار عبر الاحتياطي الدوري (تحديث كل ~3 ثوانٍ). الكود يستخدم `postgres_changes` القياسي. بعد الإعداد تحقق من ظهور «مزامنة لحظية».
- **رفع الصور إلى Storage** وإرسال **بريد التأكيد واستعادة كلمة المرور**.
- النشر على Vercel.

اتبع قسم [اختبار الاتصال](#اختبار-الاتصال-بين-المعلم-والطلاب) بعد إعداد Supabase لإكمال التحقق، أو شغّل `npm run test:e2e` مع `E2E_BASE_URL` و`E2E_SUPABASE_URL` و`E2E_ANON_KEY` لمشروعك (يستحسن مشروع اختبار منفصل).

### البيانات التجريبية
لا يحتوي التطبيق على بيانات تجريبية مختلطة ببيانات الاستخدام. الاختبارات تنشئ قواعد بيانات ومستخدمين منفصلين (`@test.local`). للتجربة اليدوية يوجد «قالب CSV نموذجي» في صفحة الاستيراد بأسئلة عامة (رياضيات وعلوم) موسومة «مستورد»؛ وتعمّدنا ألا يحتوي نصوصًا شرعية.
